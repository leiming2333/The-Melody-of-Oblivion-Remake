# 高风险代码覆盖率门禁

运行 `npm run test:coverage`。它运行与 `npm test` 相同的完整测试集，并用 Node 内置的 V8 测试覆盖率采集器检查以下四组代码，不增加第三方覆盖率依赖。

| 代码组 | 行覆盖率下限 | 分支覆盖率下限 | 函数覆盖率下限 |
| --- | ---: | ---: | ---: |
| `src/main/accounts/**/*.js` | 85% | 75% | 85% |
| `src/main/updater/**/*.js` | 90% | 73% | 78% |
| `src/main/minecraft/downloader.js` | 85% | 80% | 85% |
| `src/main/minecraft/modpack-*.js` | 88% | 72% | 82% |

阈值定义在 `scripts/coverage-thresholds.json`。初始值以 2026-11-24 的 Windows / Node 26.10.0 全量测试为依据，四组行覆盖率分别约为 88%、95%、90%、92%，分支约为 80%、79%、89%、77%。保留少量平台差异空间；增加测试后可逐步提高阈值。任何一个组、任何一项低于下限都会让命令失败，比较使用原始数值，不使用四舍五入后的展示值。

脚本独立枚举匹配的源码文件：没有出现在报告中的文件、完全未执行的文件、匹配不到源码的组也会失败，避免新增未测文件被 Node 默认的“只统计已加载模块”行为忽略。组内覆盖率按行、分支、函数的实际计数加权，不对各文件的百分比简单取平均。

输出位于被 Git 忽略的 `coverage/`：

- `report.md`：每组阈值、覆盖率与逐文件结果。
- `summary.json`：门禁结果和实际计数。
- `raw-summary.json`：Node 原始报告，包含未覆盖行、分支及函数，便于补充错误路径测试。
- `tests.log`：该次完整测试输出。每次运行会清理旧报告，失败运行不会复用旧结果。

快速检查工作流通过 `npm run test:coverage` 执行一次全量测试，始终上传报告，并把分组结果写入该次 Actions 运行摘要。发布构建仍执行原有测试与打包验收；代码覆盖率不能替代真实登录、全平台启动和升级验收。

Node 测试进程通过继承的覆盖率环境采集正常退出的 Node 子进程。后台进程若被强制终止，或代码在独立 Electron 运行时内执行，覆盖率数据可能无法完整回传，因此这些边界仍需直接模块测试与运行时验收。不要把缺失的数据当作已覆盖，更不要为通过门禁排除失败路径。当前四组的源码均在直接模块测试中加载，缺失文件检查会阻止静默遗漏。
